# Temporal board-reference experiment: result

I tested the board-anchored direction on saved, nonfinal SFP episodes. The idea was to detect two fixed board endpoints in the three wrist cameras and combine sightings over the robot's last three seconds of measured motion. A reliable 3D board reference could then support numbered-slot memory.

The existing RGB endpoint predictions gave an accurate early board reference in **1 of 10** grouped development scenes. As a control, I supplied the true projected pixels to the same temporal geometry code, first exactly and then with fixed 3 px noise. Both controls gave **10/10**. This is a privileged diagnostic, not a usable perception result: it shows the camera geometry and measured movement can work if the landmark pixels are accurate.

I then tried two bounded repairs. A constant pixel correction learned only on training groups gave **0/10**. A new small model looked at a **160×160 crop from the original 1152×1024 image**, centered by the old RGB model's prediction. It trained for 2,000 updates on **16,145 labeled crops from 70 training groups**. The ten held-out development groups had **570 observation-selected crops**, with 557 projected-in-frame labels; 555 of those labels lay in their crop. At the best checkpoint, landmark error was **9.92 px median / 32.17 px p95**, versus the planned **3/8 px** limit. The unchanged temporal geometry check rose to **3/10** accurate early board references, still below the **9/10** gate. Five scenes had no early accepted reference; two more had accepted but inaccurate ones.

I inspected [example original-image crops](../../outputs/experiments/2026-10-07_sfp_rail_original_crop_refiner_v1/development_diagnostic_crops.jpg). Green circles are CAD projected labels; red circles are the model. Easy examples align, but some projected points fall on plain board edges or repeated card structures where the exact point has no unique visual mark. This is my qualitative inspection, not an independent visibility review. A point being projected inside the image or crop does not prove the landmark is visible.

**Decision:** stop the current projected-endpoint board branch. I did not connect it to transport, select a port, run a new scene, or enable handoff, insertion, or RL. The four final configurations remain sealed. Board anchoring is still worth a *different* test if an independent reviewer can identify a genuinely visible fixed numbered origin in the complete public observation, or if a safe earlier view exposes one. The existing +10° view did not pass its safety/identity gate. SFP transport's separate **0/3 safe-arrival** problem also remains.
