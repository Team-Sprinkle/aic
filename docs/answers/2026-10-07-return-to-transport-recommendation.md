# Should we return to transport?

**Yes.** Transport is now the clearest independent blocker. The latest matched SFP actors reached the requested 10 mm buffered approach region on **0/3** new nonfinal starts, even though all four matched CheatCode controls inserted. They stayed below the 300 ms inference limit, so the measured failure was the route, not runtime speed. A corrected actor improved held-out teacher-action p95 from **2.717 to 2.153 mm**, but still missed the live region on all three starts. This is why another small improvement in one-step imitation is not enough.

There is a concrete transport hypothesis: **the actor is underusing the requested card/port code when it chooses its route.** In a same-image diagnostic, changing among all ten request codes changed its first target by only **0.554 mm median**, while matched teachers on paired same-board requests differed by **12.44 mm median** during an early route branch. The SFP training set is also skewed: **233/297** episodes request card 0/port 1, while the other nine requests have only 5–8 examples each. These observations do not prove task conditioning is the only cause; autonomous off-route drift and action execution still matter. But they give us a targeted repair to test.

I recommend the following bounded sequence:

1. Freeze the current actors and use their saved traces/videos to pinpoint the **first route-choice divergence** on each failed development start. Compare requested code, image/history, commanded TCP-body chunk and measured TCP motion against its matched teacher. Separate a wrong route decision from controller tracking or camera/state timing errors.
2. Train **one matched full-action transport actor** that feeds the task code into the temporal visual representation *before* route decisions and supervises a **discrete request-specific route stage/choice** alongside the existing full TCP-body action targets. Keep one shared actor for normal transport and later recovery; do not add a delta-action correction head or privileged true-port geometry. Use the existing paired-request episodes and a group-balanced sampler, checking that the rare requests still have independent complete groups. Compare it with the current actor under the same split and update budget. A previous direct next-waypoint regressor missed its held-out error gate, so I would not simply reuse that head. Check same-image task-code sensitivity against paired teacher actions, but do not mistake that offline check for live success.
3. If the offline route-choice check is meaningful, test on **three new nonfinal starts** covering different requested cards and card counts, with no ground-truth target input or learned handoff. Use simulator geometry only after rollout to score the requested buffered region. Require **at least 2/3** safe arrivals within 10 mm, no increase in scored contact and complete inference p95 below 300 ms. If it passes, expand to a ten-start grouped development check with a 9/10 target. If it fails, diagnose the first divergence and either repair that specific representation/control issue or stop this architecture branch.

I would keep the precise local port refiner and the independent full-public-observation identity review as a **separate prerequisite** for handoff. The new board-origin audit shows that a fixed board point cannot replace local port vision: even a true screw position plus true board yaw left **15.02 mm median** opening error and two wrong-opening matches in ten scenes. The transport actor can be improved and scored without claiming that automatic insertion is ready. RL should remain gated until a supervised actor reaches the approach region reliably enough to give recovery training meaningful starts.

This returns effort to the part of the pipeline that currently fails first, with one hypothesis and a live stopping rule.
