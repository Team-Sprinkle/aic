# Suggested next step after the SC orientation audit

I suggest **fixing selected-port recognition before any insertion or RL training**. The orientation correction now does its mechanical job: it brought the TCP within about 0.1° of the image-derived target in the tested port-0 runs. The blocker is that the original identity model rejects that corrected view, while the model trained without TCP orientation falsely accepts a physically absent port. Neither is a safe handoff.

The next test should use **physically matched view pairs**. On fitting-only Gazebo resets, hold near the port, rotate the TCP through a small bounded range, and record the *new three-camera images and measured TCP pose at each angle*. Include selected port 0 and 1, both-port scenes, one-port scenes with an absent requested port, and some partial occlusion. A port that remains identifiable should retain its identity across the real view change. Only pair views for a consistency loss if inspection confirms it remains identifiable in both; absent requests remain negatives throughout. Do not use an unchanged image with a fabricated different TCP quaternion for training. That same-image swap was useful for diagnosing sensitivity, but the cameras move with the tool.

Run a small matched comparison with the existing spatial identity architecture: one head retains the TCP quaternion but learns from the real paired views, and one removes it. Give both the same fitting reset groups and update budget. Keep the current RGB locator, board-angle correction, pose estimator and good saved handoffs frozen. Freeze new complete-reset development scenes before fitting. I would budget **at most two GPU-hours for these two fits**, plus a small targeted capture/review pass, and stop before live integration if the offline gate fails.

The gate is strict: zero all-camera accepts of a physically absent requested port on **each** held-out reset; at least 95% recall on manually reviewed clear real-port arrivals; all four saved good handoffs retained; corrected port-0 images accepted; and saved wrong/hidden requests rejected. If that passes, repeat fresh native-RGB shadow runs and measure complete inference latency below 300 ms before attaching the insertion actor. If absent-port confusion persists, stop classifier retraining and try an explicit observation-derived board/rail landmark selector with an `invalid` output, under the same gate.

This choice keeps the useful spatial layout and multiple-camera evidence. It is consistent with the spatial-representation ideas in [Transporter Networks](https://proceedings.mlr.press/v155/zeng21a.html) and the multi-view consistency idea in [S3K](https://proceedings.mlr.press/v155/vecerik21a.html); those papers do not establish that this particular SC gate will pass. The [experiment record](../experiments/2026-10-03-sc-orientation-identity-repair.md) now states the physically matched-data requirement. Keep insertion, RL and final scenes sealed until this gate passes.
