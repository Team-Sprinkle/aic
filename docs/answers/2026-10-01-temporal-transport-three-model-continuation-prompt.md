## Evidence and scope

The current single-observation transport transformer uses three current RGB images, a 32D robot state, and a 10D task code. It predicts four TCP-body-frame commands over 200 ms. The task code identifies SFP versus SC, selected port 0/1, and selected SFP card; it does **not** provide the target's 3D position. It has no past-image/action history. Four BC variants on the existing 83 SC and 236 SFP training episodes failed **0/16 stable 10 mm handoffs** on two opened SC development layouts across 20 and 60 mm command caps. The cap mismatch was real but increasing it did not repair autonomous routing. Early wrong-stage movement and later drift are observed; the exact cause remains unproven. The earlier PoseInsert-style deterministic transformer succeeded at **local 8 mm Isaac SFP seating** from privileged near-port resets; that is neither normal-start transport nor official full-depth Gazebo insertion. Do not generalize the earlier diffusion comparison into a claim that diffusion cannot work for transport.

Audit their timing and cause. Keep causal hold boundaries, sparse samples, measured settling/contact, and elapsed durations; avoid letting repeated nearly identical hold frames dominate the loss. Never infer route completion from elapsed time alone. Do not use teacher plan stage, true target geometry, or simulator pose as a deployable input.

Define route-stage labels, the **next complete TCP subgoal in the current TCP frame**, and an observable handoff/stop label from teacher plans and measured events. Inspect ambiguous transition examples visually. If labels cannot be assigned reliably across both SC ports and card counts, repair the label definition before training. The goal is to let the actor remember which route segment it completed and stop near the selected port, not to force an actor to learn insertion from transport data.

## Second: implement a causal temporal transformer transport actor

Use a short, timestamped history of the three camera views, measured state, recent proposed/executed actions, and measured motion. Begin with a **2–4 s candidate history**, sampling recent observations more densely and retaining a few older keyframes or explicit route-progress state. Treat these numbers as candidates to validate against route ambiguity and latency, not unquestioned constants. Cache visual features where possible so repeated old frames are not re-encoded each decision. Encode time gaps and history masks correctly across long holds, episode starts, resets, and missing frames. Never allow a training window or cache to cross an episode/reset boundary. Include the 10D task code in the temporal policy. The target's exact 3D location is unavailable to transport at deployment; if a route needs scene geometry, infer it only from ordinary observations. Compare against the frozen single-observation BC checkpoint under identical splits and development scenes.

Use a transformer over temporal observation tokens, with a stage/progress head, TCP-frame next-subgoal head, and handoff/stop head. Keep full actions or subgoals, **not additive delta corrections to another actor**. Make the stage decision depend on observed progress and measured TCP movement. If a waypoint controller is used, it must consume only predicted subgoals plus measured state; any teacher-plan route at runtime invalidates the autonomous test. Log all predictions, executed commands, measured motion, stage transitions, and safety stops.

Determine the command horizon from real runtime data. Start with the existing **four 50 ms commands per 200 ms decision**, executing all four while checking force/stall at each control tick. Complete inference p95 was as high as about 183 ms in the previous system, so do not assume 50 or 100 ms replanning is feasible. Benchmark the new full path, including three cameras, history encoding/cache, transformer, and ROS command generation, with p50/p95/p99. Change the number of commands executed per prediction only if measured latency and closed-loop tests justify it; document the resulting target/execute cadence and account for action changes at stage boundaries. Keep complete inference p95 below 300 ms.

Run one bounded, hypothesis-driven supervised experiment first: one GPU, at most 6,000 updates or 2 h for the initial temporal/stage candidate, with a declared held-out plateau rule. Use episode-balanced sampling and inspect by task, SC port, card count, route stage, and hold/motion phase. Suggested offline gate: at least 90% held-out stage accuracy, next-subgoal translation p95 at most 20 mm, no skipped stage in trace replay; tighten or revise these thresholds if the teacher/controller tolerance audit shows they are inappropriate. Include one controlled ablation of history versus the same model without history. Do not start a broad parameter sweep or routine new data collection.

If the offline gate passes, freeze the candidate and run the same two existing, non-final SC development starts, at most two 70 s rollouts initially. Require the correct around-card route, acceptable force/contact, and **stable** handoff within 10 mm rather than a transient near miss. Report lateral, axial, 3D, and orientation errors at handoff, official insertion score separately, and video/causal trace of first divergence. If either fails, diagnose the specific failure and make a bounded targeted repair; do not claim success from offline errors. Only then test new episode-grouped development starts and SFP transport. Preserve all unsuccessful checkpoints and results. Keep four reserved final configurations sealed.

## Third: task-conditioned perception

After the transport experiment is resolved, audit existing RGB and simulator-label provenance, per-camera calibration, and any visibility-label defects. Train the selected-target perception model using the task code; distinguish the requested port from other visible ports. Train on selected-target pose **when observable**, per-camera identifiable visibility, and calibrated fused-pose confidence. Offscreen/fully occluded selected targets should have negative visibility and masked pose loss, not fabricated pose labels. Include partial occlusion, wrong-port negatives, both SC ports, SFP card identities, and near-port scenes. Simulator geometry may produce training labels only; it may not select runtime crops or provide deployment inputs. Use whole-episode/reset splits. Measure axial/lateral/3D and orientation error, false confident predictions, and coverage by task and phase. Confirm whether it reliably resolves the 0.5 mm insertion corridor before allowing handoff.
