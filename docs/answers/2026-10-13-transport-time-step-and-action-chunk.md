# Transport timing: prediction versus execution

**October 13 update:** the [longer-horizon comparison](2026-10-13-longer-transport-chunks-result.md) also trained 8-predict/4-execute and 12-predict/6-execute variants. The description below is the original four-target runtime; the corrected live comparison uses a post-inference simulation-clock schedule to ensure the requested prefix is actually issued.

For the current route-diffusion **transport actor**, one control command slot is **50 ms** because the live runner is set to **20 Hz**. At each policy decision it predicts **four TCP pose targets**, intended for successive slots at approximately **0, 50, 100, and 150 ms**. That is a **200 ms action chunk**. These are full target poses relative to the TCP at the chunk's observation, not four incremental deltas to add together.

The normal live setting executes **all four predicted targets**, one per 50 ms slot, and then gets a new observation and predicts the next four. Each target is converted into a Cartesian command using the latest measured TCP state, with per-command translation and rotation clamps. If inference or simulation timing makes a later chunk member stale by more than one slot, the runner drops that member. Thus four is the planned count, while the actual issued count can be smaller on a slow decision. An optional diagnostic flag can replan after every command, but it is **off** in the recent matched runs.

The phrase **“four diffusion steps”** in the latest experiment refers to how many neural-network denoising iterations are used to *generate the whole four-target chunk*. It is separate from the four 50 ms commands. The previous sampler used 12 denoising iterations to generate the same four commands; the faster pilot used four iterations.

Recent slow first inferences took hundreds of milliseconds, so the first policy decision could arrive late relative to the ideal 200 ms decision cadence. This was part of the transport failure diagnosis. The teacher cache is approximately 200 ms between decisions, with 50 ms target commands inside each chunk; exact source timestamps can vary, so training uses the recorded targets rather than assuming every raw bag is perfectly periodic.
