# SFP anchor continuation — October 4, 2026

I continued beyond the previous middle-card detector instead of stopping at its 7/10 early-acquisition result.

I built an observation-selected crop around the requested SFP rail slot using a frozen RGB prediction of another card's two ports, the task's card/port code, measured TCP, camera calibration, and the board's 40 mm rail spacing. True port geometry was used only afterward to score the crop. On the same ten saved development episodes, a fixed 12 px source-pair rule placed the true target inside all three 480×480 original-image crops on **95/102 proposals**. On the 50 training episodes it did so on **423/435** proposals; most training misses were because the true target was outside at least one camera view.

One bounded 1,200-update crop-refiner fit finished on GPU 2. Its selected update 800 accepted **37/59** strict-rule development proposals, with no accepted wrong port and **2.70 mm** accepted 3D p95. Keeping that model frozen and using the 12 px crop proposals gave **59/102** accepted, no accepted wrong port, and **3.98 mm** accepted 3D p95. Poor predictions remain among rejected crops, so the accepted-error number should not be read as overall pose accuracy.

A read-only combination of four frozen locators acquired the requested port in **9/10 episodes within three seconds** and **10/10 eventually**, with no accepted wrong port or >10 mm disagreement between simultaneously accepted estimates in these saved episodes. The tenth, card 3/port 0, first acquired at **3.086 s**. The checkpoints were selected using these same development starts, so this is **exploratory**, not an independent generalization result or an autonomous insertion result. A conservative two-model consensus covered only 6/10 early episodes.

I also profiled the complete four-network image stage on 20 saved three-camera observations. JPEG decode, resize, crop, and forward passes took **176.8 ms p50 / 201.8 ms p95 / 207.8 ms p99** on one RTX A6000. This excludes camera transport, ROS, triangulation, the actor, and the controller; therefore it does not prove the required full live p95 is below 300 ms.

At the time of this experiment, fresh non-final Gazebo resets could not launch because rootless Docker hit UID 1008's **200/200 key quota**. A later cleanup removed 25 audited stopped AIC containers. The count was 199/200 before and after that cleanup, and a minimal sequential container start now succeeds. The active old Isaac container on GPU 0 was not interrupted. No actor, insertion policy, RL, or final-scene run was started in this experiment.

**Next experiment:** once safe rootless startup is available, freeze these predictors and run ten new complete, non-final SFP resets, one for each requested card/port. Score acquisition by three seconds, every accepted wrong-port identity, coarse 3D p95, disagreement, and complete live inference p50/p95/p99. Stop if any wrong port is accepted, fewer than 9/10 requests acquire early, accepted p95 exceeds 20 mm, or full live p95 reaches 300 ms. A passing perception result would still need a separate safe autonomous transport and insertion gate. If it fails, use the first failed view to test one specific observation-only slot or source-pair repair rather than broad retraining or threshold tuning on the same saved scenes.
