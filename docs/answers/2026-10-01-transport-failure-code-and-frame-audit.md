# Why the transport policy fails: task, frame, data, model, and runtime audit

Date: 2026-10-01. This audits the **cleaned SC Low Lateral Bypass transport BC** and its frozen temporal follow-up. It does not claim to have found one proven root cause or to have run a new SFP rollout. Reserved final scenes remain sealed. No training or new Gazebo rollout was run for this audit.

## Direct answer

The demonstrated live failure is **SC-to-SC transport**: 16 previously recorded autonomous runs on two non-final SC layouts reached 0 stable 10 mm handoffs and 0 full insertions. The clean checkpoint's best final handoff error was 103/194 mm on the two starts, and all four checkpoint/cap variants failed. **We do not yet know whether the same closed-loop failure occurs on SFP-to-NIC**, because this cleaned shared checkpoint has not had a matched autonomous SFP rollout. SFP has only offline teacher-frame checks: the clean checkpoint's held-out first target p95 was 6.70 mm, compared with 4.16 mm for SC. Those values cannot establish autonomous success. The earlier local PoseInsert/SFP result concerns a near-port insertion controller, not this normal-start transport actor.

The source training set was **236 SFP and 83 SC complete training episodes**, with 32 SFP and 21 SC episode-grouped validation episodes. The 104 SC episodes are scored full insertions using the new Low Lateral Bypass route. The SFP source is highly skewed: 227/236 training and 31/32 validation episodes target card 0, port 1. SC training covers both selected ports (35 port 0, 48 port 1) and card counts 1–5. The SC task vector contains family and selected port, **not card count**; the camera images are expected to reveal the layout.

## Which coordinate frame is actually used?

For **transport**, the model predicts four **complete target TCP poses relative to the observed TCP at the start of the chunk**. This is a body-frame pose target, represented as XYZ plus two rotation-matrix columns (9 numbers per target). It is not a residual added to another actor's action, and it is not a target-port-frame prediction. If the current observed TCP pose in `base_link` is $T_{B,C_0}$ and the network predicts $T_{C_0,G_i}$, the runner forms the absolute goal

$$T_{B,G_i}=T_{B,C_0}T_{C_0,G_i}.$$

Before dispatching member $i$, it recomputes $T_{C_i,G_i}=T_{B,C_i}^{-1}T_{B,G_i}$ from the latest measured TCP, clamps translation/rotation, and sends the resulting **absolute base-link Cartesian pose** to the existing API. Thus the predicted goal stays anchored to the decision observation, while execution accounts for measured motion between chunk members.

The separate proposed **local insertion** path uses a predicted selected-port pose and port-relative target actions (PoseInsert style). It has not yet been integrated into these full-start transport rollouts. The transport checkpoint explicitly sets `target_frame='body'` and disables the pose head as an action input. The pose head weights exist in the reused network class but are frozen/unused for this checkpoint. There is no hidden ground-truth port transform in autonomous transport.

## What the network actually is

The deployed BC actor is **not a diffusion model or diffusion transformer**. It is a deterministic, roughly 13.6M-parameter model: a shared ImageNet-pretrained ResNet18 processes each of three cameras; attention merges their global image vectors; an MLP combines that with measured 32D robot state and a 10D task code; a two-layer Transformer Encoder processes four learned action-position tokens and outputs four 9D TCP-body target poses. The action-token transformer has **no history of previous observations**. It also does not retain image patch tokens or explicit spatial port/card detections. [Training code](../../scripts/train_clean_transport_bc.py) · [network](../../scripts/train_shared_port_tcp_bc.py) · [runner](../../aic_example_policies/aic_example_policies/ros/RunSharedPortTCP.py).

The later temporal candidate adds a separate two-layer transformer over cached **frozen** visual/context features and causal past commands/measured motion. It is also deterministic, not diffusion, and never passed its offline subgoal gate, so it has no live rollout. Its previous-action history in offline evaluation comes from teacher actions; a deployed policy would have its own earlier actions instead. The frozen feature also comes from the failed single-frame transport actor, so the temporal head cannot recover image detail that encoder discarded. [Temporal record](../experiments/2026-10-01-temporal-three-model-continuation.md).

## Findings that could explain the gap

1. **Small teacher-frame errors accumulate in closed loop.** The clean actor's 4.16 mm SC p95 measures one recorded target on a teacher observation. It is not a 70-second route error. In the saved port-0/two-card divergence, after one second the policy's command is missing much of the teacher's sideways motion and commands down instead of up; measured TCP separation is already 22 mm, then 58 mm at two seconds. Once it leaves teacher states, BC has not learned the corrective behavior. [First-divergence trace](../../outputs/experiments/2026-10-01_sc_llb_cleaned_bc/autonomous_transport/motion_safe_port0_two/first_divergence.json).
2. **The selected-port code reaches the model but has weak influence on this checkpoint.** On the same saved SC live observation, switching only port 0↔1 changes the first target by 0.30–0.77 mm at five sampled times in each of two runs. On 21 held-out teacher episodes sampled early, midway, and late, the median effect is 0.37, 0.49, and 0.48 mm. Swapping the entire image triplet with another held-out scene changes it by about 1.8–2.1 mm median; this is an out-of-distribution sensitivity check, not a physical counterfactual. The code is correctly supplied; the learned policy appears to use it weakly. It may partly be because much of the initial around-card route is shared between ports, and these substitutions do not recreate the other port's physical scene. [Task sensitivity](../../outputs/experiments/2026-10-01_sc_llb_cleaned_bc/transport_task_sensitivity_teacher_frames.json) · [image sensitivity](../../outputs/experiments/2026-10-01_sc_llb_cleaned_bc/transport_image_sensitivity_teacher_frames.json).
3. **The architecture lacks an explicit progress state.** The action-token transformer does not remember which route stage has finished or whether a 5–8 second planned hold has settled. The later causal-history candidate improved offline stage/subgoal estimates but still failed the 20 mm subgoal gate (best full-held-out p95 39.50 mm). At the tilt-hold→return boundary, adjacent observations are almost identical, so stage classification can switch too early or late. This is an offline ambiguity, not evidence of a card collision.
4. **The tested runner is transport-only.** It has no validated perception-confidence handoff to the separate local port-frame insertion actor. Even perfect transport would need that integration for full insertion. The present decisive failure is earlier: it does not stably reach the 10 mm handoff corridor.
5. **Input and runtime distribution shift remain possible.** The source images precede commands by up to 48 ms, the learned runner can skip late chunk members, and the TCP quaternion has a sign discontinuity near a 180° orientation. A prior saved sign-flip probe changed the first target by roughly 1–2 mm for two mathematically identical quaternions. That probe used an older checkpoint, so the impact on this clean checkpoint is unmeasured. These effects are plausible contributors, not proven main causes. Future checkpoints should use a continuous rotation representation or sign-invariant encoding and verify exact image/state timestamps at inference.

## Concrete code issues fixed in this audit

- The transport-only runner previously returned `True` after its bounded runtime even though it has no insertion detector. It now returns `False` on timeout. This changes the action result semantics, not the saved official scores or the frozen rollout trajectories.
- The camera-preprocessing audit constructed a body-target checkpoint with pose conditioning accidentally enabled. It now reads `target_frame` from the checkpoint. The SC direction audit likewise read body checkpoints as port-frame targets and used the old camera loader; it now selects the correct frame, pose-conditioning flag, and preprocessing. These were **diagnostic script bugs**, not the training/runtime path used for the 16 rollouts.

Python syntax checks and `git diff --check` pass for these edits. No new checkpoint or Gazebo result is claimed.

## Next discriminating checks

First, run **one bounded autonomous SFP development rollout** with the same frozen clean checkpoint and 70-second budget, with the official score and handoff trace. This answers whether the failure is visibly SC-specific; the skewed SFP validation set alone cannot answer it. Second, on saved SC starts, compare teacher and model first actions at the **same measured state** across route stages, and separately quantify how often a sub-5-mm command error reverses the intended lateral or vertical direction. If the earliest command already points wrong, fix conditioning/representation before more data collection. If early directions agree but later stages fail, implement an explicit observation-only route-progress controller with measured stage completion; test it under a fixed two-start budget before retraining at scale. Keep the final split sealed and do not start RL until the transport/handoff and local insertion gates pass.
