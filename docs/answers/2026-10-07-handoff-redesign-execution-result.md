# Handoff redesign: first execution result

I executed the first bounded perception redesign and the separate transport upper-bound diagnostic on saved **nonfinal** SFP scenes. The result is a useful negative: **no new model cleared the identity/accuracy gate, so I did not connect it to transport or enable handoff.** No autonomous insertion, RL, final-scene evaluation, or new Gazebo collection occurred. GPU 1 was the only new training GPU used.

## What I tested

1. **Could we simply rename better candidates?** On a frozen ten-request replay, I ignored the old detector's card labels and asked whether *any* of its ten three-camera candidate points lay within 20 mm of the actual requested opening. This happened early in only **4/10** scenes; its named requested channel was correct in **3/10**. Thus a better association rule over this fixed set cannot supply the target in six scenes. True port positions were used only to score the already saved predictions.
2. **Could local board-slot features generate the missing point?** I froze the existing board model, read its three-camera local features at predicted numbered slots, and trained a small head on **70 complete-reset training groups**. The first version predicted a port point independently in each camera. It finished 2,000 updates, but the selected checkpoint passed three-camera geometry in only **one row/one of ten early development groups**. The per-camera points often disagreed by tens of pixels. Two failed loader starts were preserved and repaired before this fit; they performed zero updates.
3. **Would one shared 3D prediction fix that?** A second head predicted one base-frame 3D port point from measured TCP and the images, plus an uncertainty value, so all camera projections were geometrically consistent. It also completed 2,000 updates. The selected checkpoint did find a correct point early at least once in all ten development groups, but it **accepted five wrong neighboring ports**, with **39.75 mm** accepted p95 error. Only **48.7%** of points accepted under its predicted 20 mm uncertainty were actually within 20 mm. This fails both the accuracy and safe-abstention requirements.
4. **Would an explicit target cue help the frozen transport representation if perception were perfect?** This was a *privileged, offline-only* comparison: matched full-action heads received either zeros or the true port-to-TCP vector. The first attempt used poorly scaled metre inputs and is retained as a failed setup. With a fixed 0.1 m normalization, both heads trained for 1,000 matched updates on **50 training groups** and were evaluated on ten disjoint development groups. Early teacher-observation first-action p95 improved only **1.905 → 1.850 mm (2.9%)**, below the planned 20% gate, while overall p95 slightly worsened **2.019 → 2.029 mm**. This does **not** show that target cues cannot help autonomous transport: the offline teacher observations were already easy to imitate and contain no meaningful off-route recovery challenge. The oracle weights are never deployable.

## What this changes in our direction

The present failure is more basic than crop width or a stop threshold. In hard scenes the target point may be **absent from the candidate set**, while a direct 3D regressor can be confidently close to a **different card**. I stopped this representation branch rather than tuning on the same ten development scenes. The existing coarse model and transport actor remain the active baselines, with automatic handoff disabled. The four reserved final configurations remain sealed.

The next distinct perception experiment should begin with the **independent review of the corrected 30-panel packet**, which includes the public measured TCP pose missing from the first RGB-only review. If the board's numbered origin is visible at some point, test a temporal board-coordinate map that remembers slot order across measured motion and can abstain when origin evidence disappears. If it is not observable in current views, test one safe earlier inspection posture that exposes it. For transport, the next comparison needs autonomous off-route states and route-level target supervision; another frozen-head teacher-action fit will not answer why live routes missed 0/3 safe arrivals. A predicted target cue can drive the actor only after it passes a new grouped identity gate with zero wrong-port accepts.
