## What the experiments found

1. **Changing the existing transport stop threshold cannot make it reliable.** On seven saved SC routes, a probability threshold of 0.8 gave five safe pause proposals and two false ones. Raising it to 0.99 still left both false proposals and lost all five safe arrivals. A new small head trained on 9,960 saved actor decisions passed its tiny validation set but failed the frozen routes: **one safe and six false proposals**, compared with **five safe and two false** for the original head at the same selected threshold. I did not deploy it.
2. **The SFP auxiliary depth camera cannot currently provide visibility labels.** In two bounded rootless Gazebo captures, using attached and world-follower RGBD cameras, every auxiliary pair from simulation time 5–40 s had invalid depth and a flat-gray image. The ordinary wrist cameras still showed the task. I rejected those frames and stopped repeating the same sensor approach.
3. **A projected opening is not proof that the opening can be seen.** I reviewed a [three-camera gallery of original SFP images](/home/nas/chmin/aic_archives/2026-10-02_selected_port_handoff/sfp_projection_review_early_10x3.jpg) with ground-truth projection markers used only for audit. Several markers fall on the plug when it blocks the opening. The gallery is evidence for an explicit visibility review; it is not a training set of certified visible labels.

The safety rule is now clearer: transport can *propose* a pause, but precise perception must reject a wrong-route or wrong-port proposal before insertion starts. The gate must measure **false accepted handoffs**, missed good arrivals, and repeated pauses. The present head and visual verifier have not passed that gate.

## Current state and next bounded experiment

The selected-port perception model and integrated handoff remain **open**. Training them now with projected-in-frame flags or invalid depth would produce misleading visibility labels. The next experiment uses existing synchronized original wrist RGB, rather than collecting more Gazebo rollouts: review about 100 balanced examples across SFP and SC, including hidden ports and visible neighboring ports; compare a small RGB-only selected-target visibility pilot with the frozen in-frame baseline on episode-grouped holdout. Budget: one workday of label/tooling review and one GPU-hour of fitting. Continue only if at least 95/100 reviewed labels agree with the images and the known hidden/wrong-port examples have zero false-visible calls without rejecting most clearly visible targets. If that fails, repair the label source before training a new pose model.
