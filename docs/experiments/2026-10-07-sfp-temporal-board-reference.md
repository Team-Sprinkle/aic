# Causal temporal board-reference feasibility

**Hypothesis:** the existing RGB rail-endpoint detector is inconsistent across cameras in a single frame, but the physical board is static. Combining its endpoint pixels from different measured TCP poses may recover a stable slot-zero and slot-four reference without simulator geometry at runtime. This tests the key board-memory idea before training a new landmark network.

## Frozen diagnostic and stopping rule

Use the existing frozen slot-local board checkpoint and its saved predictions on ten complete grouped development episodes; do not tune its weights or rail labels. At each saved decision, retain only predicted endpoint observations from the preceding **3 s** with predicted in-frame probability ≥0.5. Fit each static 3D endpoint by deterministic ray-pair hypotheses and a **5 px** reprojection inlier rule. Require at least three inlier views spanning two camera names and two distinct times; refine from inlier rays. Accept a pair only if their separation is **120–200 mm**, consistent with the 160 mm nominal CAD span. No simulator board pose or true endpoint projection may select a hypothesis. Use true projected endpoints only **after** the fit to score 3D error.

The development feasibility gate is early accepted board reference in **at least 9/10** groups within 3 s of the first saved observation, with both endpoints within **10 mm** of scoring geometry, and zero accepted references whose slot-zero/slot-four ordering is reversed. If it fails, stop this frozen-endpoint temporal branch before any new-scene or actor test. If it passes, freeze the rule and evaluate once on separate nonfinal groups, then check candidate association and full runtime latency. A board reference by itself is not a safe requested-port handoff.

The 30-panel RGB/history/public-TCP packet at `/home/nas/chmin/aic_archives/2026-10-07_sfp_blind_review_followup_v1/` remains independently unreviewed. My inspection of its first contact sheet is qualitative single-reviewer evidence only: side views often show several installed cards, while the center view can clip the row. It does not certify a visible numbered slot origin or a 30-panel identity rate. No sealed target mapping was opened for that inspection.

## Frozen RGB result and geometry-conditioning control

The causal 3 s RGB-prediction fit accepted an early board reference in **5/10** grouped development episodes, but only **1/10** had both endpoints within 10 mm of scoring geometry; no accepted pair had reversed slot order. This fails the predeclared 9/10 gate. The frozen endpoint model's individual-view predictions can appear visually close to projected CAD marks, but the multi-view/temporal rays still disagree enough to produce incorrect 3D endpoints. Stop this *frozen landmark* branch before an actor or new-scene test. [Per-decision and per-episode result](../../outputs/experiments/2026-10-07_sfp_temporal_board_reference_v1/summary.json).

One read-only control can isolate camera geometry from detector error: replace the RGB-predicted endpoint pixels with the **true CAD projections**, once exactly and once with fixed-seed 3 px independent Gaussian pixel noise, leaving the same measured TCP trajectory, 3 s causal window, ray fitting, and acceptance rule. These projections are explicitly privileged and never a runtime input. If the 3 px control clears 9/10 early accurate references, detector localization/visibility labels are the bottleneck. If it also fails, audit calibration and viewing baseline before training another landmark model. Do not use these controls to tune a new threshold.

**Control result:** exact and 3 px fixed-noise true-projection controls both reached **10/10** early accurate references with zero reversed order. The measured TCP motion and calibration are adequate if endpoint pixels are accurate to roughly this scale. On frozen development predictions, visible-endpoint pixel error was **12.0 px median / 34.7 px p95** overall; per-camera/end medians were about 10–15 px and only 2.5–7.6% of individual predictions fell within 3 px. This makes the current detector the dominant measured bottleneck. The control is privileged and supplies no deployable endpoint.

Before a new crop-refiner fit, test a simpler train-only calibration: estimate one constant 2D residual vector per camera/end from frozen in-sample training predictions and CAD projections, apply those six fixed vectors to untouched grouped-development predictions, then rerun the *same* temporal reference gate. This can remove systematic bias but cannot repair view-dependent occlusion. Require the same 9/10 early ≤10 mm reference result; otherwise stop this constant-offset branch. No development-scene offset fitting or threshold tuning.

**Constant-offset result:** fixed train-only median residual correction changed per-view development errors little (roughly 10–14 px medians, still up to 47 px p95) and produced **0/10** early accurate temporal references. It cannot explain the image-dependent pixel errors. The train and development proposal centers do, however, contain the projected endpoint within a **160×160 original-resolution crop** in **16,145/16,152** eligible train and **555/557** eligible development camera/end observations. This join uses the train-only filtered row indices; an earlier ad hoc count using the unfiltered global index was invalid and was not used in any model or score.

**One bounded refiner fit:** keep the frozen coarse RGB endpoint and select a 160×160 crop in the **original 1152×1024 image** around that predicted pixel. Train a small shared heatmap refiner on the existing 70 complete-reset train groups, with camera/end code and original-resolution pixels. Ground-truth projected endpoints supervise positions only; they never center evaluation crops. Select one checkpoint by projected-in-frame pixel p95 on the unchanged ten grouped development scenes, at most 2,000 updates/30 minutes on one GPU. Require development pixel median ≤3 px, p95 ≤8 px, and then **≥9/10** early ≤10 mm temporal references under the unchanged 3 s/5 px gate. If it fails, stop this projected-label refiner branch. Since projected-in-frame is not certified visual exposure, report any confident failures on occluded or ambiguous images, and do not use the fit as a deployable visibility signal. Full live latency and new-scene evaluation follow only if these gates pass.

## Original-RGB crop refiner result and decision

The refiner completed **2,000 updates** on GPU 1; the frozen ResNet-18 initialization and shared 160×160 heatmap head used **16,145** train-only labeled crops from **70** groups. The untouched ten development groups produced **570 observation-centered proposal crops**, including **557** CAD projected-in-frame labels; **555/557** labels fell inside their crop. All 570 proposal crops were refined without checking the true projection first. The checkpoint at step **1,250**, chosen by development projected-pixel p95, reached **9.92 px median / 32.17 px p95** on those 557 labels. This is a modest median improvement from the frozen **12.0/34.7 px**, far short of the declared **3/8 px** gate. The unchanged causal 3 s temporal fit improved from **1/10 to 3/10** early accurate groups, but still accepted a geometrically wrong board reference in two additional groups and had no accepted reference in five. It missed the **9/10** gate; no actor, new scene, automatic handoff or live latency test followed. I visually inspected the diagnostic crop sheet. Green circles are **CAD projected scoring labels**, red circles are **RGB model predictions**. In easy crops they nearly coincide, but several hard crops show a plain board edge, repeated card structures, or a landmark projected onto a surface with no unique visible mark. A crop can therefore contain the *projected* point while the image gives no reliable cue to its exact pixel. This is a qualitative diagnosis, not a certified occlusion annotation or independent review. Per-camera/endpoint development p95 ranges from **18.7 to 52.1 px** (left endpoint 0 is worst). Falling training loss with high grouped-development error does not support spending more updates on the same projected-label task. Stop the projected-label refiner branch.

The 3 px privileged projection controls previously achieved 10/10, so calibration and temporal fitting remain feasible if a truly observable, repeatable landmark can be found. The next *distinct* board-anchored experiment is conditional on the independent full-public-observation review: if a fixed numbered board origin is genuinely visible, define that visually grounded landmark and obtain visibility annotations on new complete groups before another fit. If it is not visible, obtain a safe earlier inspection view that reveals a unique slot origin; the prior +10° wrist view failed its position/identity gate, so it is not already approved. If neither yields a uniquely observed origin, retire board anchoring for handoff and keep automatic insertion disabled. This result neither fixes SFP transport's 0/3 safe-arrival failure nor establishes target-port identity.
