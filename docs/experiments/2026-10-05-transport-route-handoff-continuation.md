## Data and hypothesis

The verified SFP transport collection covers all five card counts and all ten requested card/port codes, but is strongly skewed: among 297 train episodes, 233 are card 0/port 1; most other requests have 5–8. The SC transport cache has 83 train and 21 complete grouped validation episodes. The most recent five successful same-board alternate requests show that the teacher routes branch measurably within 0.3–0.55 s, while a last-layer task-gated continuation improved held-out first-target p95 only 9.3%. Hypothesis: the temporal route representation must predict a future tool subgoal conditional on the public task, rather than asking only the final action map to separate targets.

The same frozen ImageNet ResNet-18 camera features, 32D measured robot state, 10D public task code, causal history and verified complete-action labels feed two matched arms. **A:** warm-started action-only temporal actor. **B:** identical warm start, with the temporal model additionally predicting the *measured teacher TCP pose one second later* in the current TCP frame; this predicted subgoal is fed to its action head. SC retains its existing stage/waypoint supervision. Model B also trains a handoff proposal output from offline safe-standoff labels. Port geometry produces SFP labels only, never a runtime model input. Both arms use identical train/development reset groups and a 3,000-update cap. A separate prior can veto handoff outside a train-fitted base-frame region; it cannot generate a positive stop by itself.

The new label cache is `/var/tmp/chmin_aic_20260918_act/sfp_paired_request_20261005/route_handoff_cache_v1/`: 39,875 causal rows. SFP safe-standoff labels use axial −100 to −70 mm and lateral ≤10 mm relative to the selected port; SC retains its local-start label. A **60 mm margin** around the training-positive TCP base-frame min/max per public request defines the veto region. It covers all 68 SFP and all 37 SC positive rows in the existing grouped validation, while rejecting 367/583 SFP and 2,010/4,440 SC validation negatives. This is only a broad prior: many negatives remain inside it. The margin is fixed here before candidate evaluation. New nonfinal scene starts remain necessary for promotion.

## Gates and stopping rules

1. Data: all requested identities and card counts represented; no validation/final reset in training; matched same-board pairs stay in training only. If label joins, camera timestamps or future state order fail, repair data before fitting.
2. Offline transport: compare A and B on unchanged complete validation episodes. Require B to improve SFP first-target translation p95 by **≥20%** over A, with no SC first-target p95 increase >10%. For SC route, stage accuracy ≥90%, subgoal translation p95 ≤20 mm, and no episode stage skips. Do not select on final scenes.
3. Handoff diagnostic: with the **train-only** potential-region veto, require zero false accepted stop events on saved autonomous nonfinal traces and timely proposals on at least 8/10 grouped teacher development episodes. Count a proposal only after three consecutive model probabilities ≥0.95; a coordinate-only region cannot propose. Report raw probability precision/recall, event counts, missed positives and failure modes separately by family and request. Keep handoff disabled if this gate fails.
4. Live test only if offline transport and handoff gates pass: first three **new nonfinal** starts, then a larger 10-start gate. Require ≥2/3 then ≥9/10 safe buffered arrivals, no increase in scored contacts, no wrong-port accepted handoff, and complete inference p95 <300 ms. Continue to refiner/insertion only after its own independent visual identity gate. RL remains off.

If model B misses offline transport gate, stop this representation branch and diagnose whether task code, visual context or short-horizon target is the limiting factor. If the handoff head fails, keep a visual pause/inspection research path separate from the actor; do not lower the region or probability gate using final scenes.

Commands, checkpoints, complete metrics, and the resulting decision will be appended below.
