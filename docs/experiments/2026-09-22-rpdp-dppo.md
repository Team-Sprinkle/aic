# RPDP trajectory BC and gated DPPO continuation

Date: 2026-09-22

> **Scope correction:** all RPDP live results in this record use a privileged
> near-opening reset and an explicit `seated_depth_m: 0.008` target override.
> The physical SFP port reference is about 45.8 mm behind the entrance and the
> cage is about 48.72 mm deep. Consequently 6/6, 8/8, and 4/5 mean successful
> **local 8 mm seating according to the Isaac surrogate**, not completion of a
> normal full episode or an official Gazebo insertion event. The local result
> remains useful, but it does not establish transport or full-depth insertion.

## Goal

Replace the unsuccessful additive action-correction design with a policy that
predicts the connector's **full future trajectory relative to the port
opening**. The selected target contains the connector pose after each recorded
teacher command at 50, 100, 150, and 200 ms. A deterministic rigid-body adapter
converts each waypoint back into its corresponding TCP-body-frame command. The
learned output is not an additive correction to ACT or to another policy.

The experiment follows the useful inductive bias from PoseInsert while adapting
it to this repository's three RGB wrist cameras, frozen observation-only pose
estimator, force/proprioception state, 200 ms decision cadence, and 300 ms live
latency requirement. Simulator geometry labels data and the privileged teacher;
the autonomous actor never receives it.

## Frame and action contract

Let (P) be the port-opening frame, (C) the connector tip, and (E) the
controlled TCP. The repaired supervised target is

\[
{}^P T_{C,t+50:t+200\,\mathrm{ms}}.
\]

The fixed grasp transform maps each proposed connector waypoint to a TCP pose.
For each successive waypoint the adapter calculates

\[
\Delta T_E = ({}^P T_{E,t})^{-1} {}^P T_{E,t+1}
\]

and emits that interval's TCP-body-frame increment. Unit tests verify
quaternion, SE(3), 6D rotation, batched-transform, distinct waypoint recovery,
and endpoint composition behavior.

The frozen visual pose estimator reports connector minus the **seated target
center** in the target frame. The RPDP target frame instead begins at the port
opening. Therefore runtime and training add the fixed target-center offset of
about 8.0006 mm along the local insertion direction. They do not rotate the
visual estimate a second time.

## Silent failures found and fixed

### Incorrect grasp orientation

The saved cable template translation was correct, but its quaternion did not
represent the TCP-to-connector transform needed by the action adapter. The
transform is now calibrated from fit episodes. Checkpoints produced before this
fix are preserved under `outputs/experiments/2026-09-22_rpdp_dppo/pre_grasp_frame_fix/`.

### Terminal geometry came from the reset scene

Isaac auto reset can occur before ordinary post-step diagnostics are serialized.
The replay correctly retains `terminal_observation`, but the first RPDP builder
still used `post_step_insertion_geometry` for terminal future waypoints. The
builder now requires the retained pre-reset terminal geometry. A regression test
constructs different terminal and reset depths and verifies that only the
terminal value is selected.

### Training used true current pose while deployment used predicted pose

The first offline adapter audit began each command at simulator-truth connector
pose. Live deployment began at the frozen visual estimate. This hid a
submillimeter train/deploy mismatch in a task with a 0.5 mm success corridor.
The replacement dataset begins conversion from the same predicted translation
and measured TCP-derived orientation available live. Simulator truth is retained
only as `oracle_current_pose9` for error reporting.

### RPDP fusion and diffusion target convention

The first local model concatenated pose and visual features into one generic
condition encoder. The replacement implements PoseInsert's central bias:

\[
f = p + \sigma(Wp+b) \odot v,
\]

where (p) is the pose/state stream and (v) is the three-camera visual and
visibility stream. This is an adaptation because the source project uses an
RGBD current/goal pair rather than this repository's three RGB cameras and
force/proprioception inputs.

The replacement also predicts the clean future pose sequence during diffusion
training (`prediction_type=sample`), matching the released PoseInsert scheduler
convention. DPPO transition likelihoods support this convention explicitly.

## First live result and diagnosis

After two tensor-shape fixes and correction of the pose coordinate contract,
the frozen RPDP-local policy ran autonomously on two development starts with no
guide, guard, exploration, or privileged actor input. It reached best lateral
errors of 0.332 and 0.309 mm, but achieved 0/2 insertions. It continued through
the useful near-opening region and eventually drifted laterally by 50.6 and
33.7 mm. This behavior agrees with the missing insertion/terminal coverage.

Complete frozen inference was 55.4 ms p50, 56.3 ms p95, and 56.8 ms p99 on one
RTX A6000, below the 300 ms requirement. Earlier submillisecond numbers measured
only retrieval of a prefetched action and were not end-to-end inference.

## DPPO gate

The code stores stochastic DDIM denoising transitions, old Gaussian log
probabilities, timesteps, conditions, and retained late denoising steps. It also
implements recomputed likelihoods and the clipped DPPO surrogate. Tests confirm
that an unchanged policy has a unit probability ratio.

The corrected frozen BC policy established a minimal 1/6 autonomous insertion
anchor with lateral error below 0.5 mm, explicit orientation, acceptable
post-reset force, and p95 inference below 300 ms. This authorized one bounded
development-only DPPO diagnostic, not promotion or access to the reserved final
split. That valid update also scored 1/6. Reward-model imagination, Dreamer,
SEER, actor-Q, and Gazebo adaptation remain disabled.

## Corrected BC and first valid DPPO continuation

The phase-complete matched run finished for all three supervised variants. All
selected their best calibration checkpoint at update 200 and stopped at update
2600 by the fixed patience rule:

| Variant | Parameters | Development endpoint xyz median / p95 | Lateral median / p95 |
| --- | ---: | ---: | ---: |
| PoseDP | 1,876,675 | 0.691 / 2.705 mm | 0.0377 / 0.2775 mm |
| RPDP-local | 1,985,899 | 0.917 / 2.952 mm | 0.0374 / 0.2872 mm |
| AIC-RPDP | 1,990,749 | 0.916 / 2.685 mm | 0.0360 / 0.3085 mm |

Despite these small teacher-distribution errors, all three initial frozen live
checks failed 0/2 and drifted by roughly 41--43 mm. Two additional causes were
then isolated:

1. The stored target trajectory was the oracle achieved future pose, while live
   conversion began at the visual current-pose estimate. This mismatch can turn
   even a perfect target label into a 0.5--0.6 mm command error. The replacement
   labels start at the observation-only current pose and compose the recorded
   TCP-body-frame commands to form command-consistent absolute future connector
   poses. Oracle future pose remains diagnostic metadata only.
2. Isaac can return a stale previous-episode render on the first sample after
   automatic reset. Dataset construction rejects this reset-transient interval,
   and deployment uses reset restoration until fresh observations are released.

The command-consistent AIC-RPDP dataset contains 666 fit, 134 calibration, and
109 development decisions from 32/8/6 complete episode groups. The adapter's
label endpoint mismatch is about 0.00003 mm. Its offline development first
waypoint command error is 0.159 mm median. Fixed-noise autonomous evaluation
achieved **1/6 strict insertions**, while variable-noise BC evaluation achieved
0/2. The successful scene reached 7.55 mm depth, 0.426 mm lateral error, and
0.075 degrees orientation error. Complete fixed-noise p95 inference was about
59 ms.

### DPPO correctness repairs

Three invalid intermediate attempts are preserved and rejected:

- The first update evaluated the diffusion transformer in training mode, so
  dropout made rollout and update likelihoods differ.
- A second attempt sampled the last denoising transition at vanishing variance;
  float32 replay serialization changed its recomputed likelihood substantially.
- A third attempt still allowed PyTorch's no-gradient attention fast path during
  rollout but used the gradient-capable attention kernel during update. Tiny
  output differences were amplified by the narrow diffusion transition.

The corrected sampler uses one explicit `1e-5` minimum variance for sampling and
likelihoods and disables the different attention inference fast path. A
save/load regression test covers this contract. On the corrected eight-episode
rollout, no-gradient and gradient recomputation agree. The initial probability
ratio was 0.9995--1.0006. The first accepted update used 156 post-restoration
transitions from eight episodes and a backtracked trust bound; its post-update
ratio was 0.9853--1.0138 with maximum absolute log ratio 0.0148. It is the first
checkpoint classified as a valid DPPO update.

The corrected stochastic collection itself achieved 0/8. Deterministic
six-scene evaluation of the valid update achieved **1/6**, the same outcome as
its BC parent. Its successful scene reached 7.546 mm depth, 0.408 mm lateral
error, and 0.070 degrees orientation error. The five failures entered the
lateral success corridor transiently but did not advance axially, then drifted.
P95 inference was 60.65 ms. This round demonstrates a valid update path but no
control improvement.

### First waypoint weighted supervised ablation

Closed-loop execution consumes only the first predicted pose before replanning,
whereas the original objective and checkpoint rule weighted all four future
poses equally. A bounded `4,2,1,1` horizon-weighted AIC-RPDP run reduced held-out
first-waypoint command error from about 0.159 mm to **0.086 mm median**. It still
scored **0/6** live. One scene advanced 0.905 mm past the opening plane and
ended at 0.291 mm lateral error, but did not seat; the other five drifted. This
is useful diagnostic evidence, not a promoted policy.

A full 32-fit-start, 75%-teacher-assisted recovery collection then extended the
earlier eight-start recovery set. It remained collection-only: simulator
geometry chose the teacher action but never entered the deployable actor. It
achieved 15/32 strict successes. The first configuration family achieved 15/16;
the second achieved 0/16 and often reached 7--13 N post-reset contact. The 17
failed sequences were preserved in the audit and excluded from positive BC.

After removing each stale first render, the rebuilt split contained 823 fit,
134 calibration, and 109 development decisions. There were 47 successful fit
sequences: 32 original teacher sequences plus 15 assisted recovery sequences.
The weighted retrain improved offline first-waypoint command error to **0.069 mm
median**, but autonomous evaluation remained **0/6** with 60.22 ms p95
inference. The model repeatedly entered the lateral corridor but backed away,
stalled axially, or drifted before seating.

### Causal temporal context ablation

The implementation review found that the first RPDP adaptation had dropped
three causal signals already used by the earlier GRU controller: change in
measured state, the prior actually executed 24D chunk, and a phase indicator.
A final matched AIC-RPDP ablation appended those signals. Its phase is computed
only from predicted relative translation and measured force; simulator geometry
does not enter the actor. This model has 2,004,329 trainable parameters.

Offline median first-waypoint error was 0.108 mm, worse than the 0.069 mm
non-temporal recovery model. Live evaluation achieved **1/6**, on a different
scene from the original BC success. That insertion reached 7.573 mm depth,
0.431 mm lateral error, and 0.164 degrees orientation error. P95 inference was
59.64 ms. Causal context is now implemented, but this matched result does not
show a reliable gain.

## Supervised BC repair continuation

The earlier 1/6 result triggered a label and runtime audit before any more RL.
Five separate problems were found.

1. **The live translation clip disagreed with the teacher.** The teacher uses
   0.2 mm alignment steps and up to 0.5 mm axial steps. Several live reports
   used a 0.2 mm clip, truncating the insertion command. Raising the ceiling to
   1.0 mm changed one frozen model from 0/6 to 1/6, but was not sufficient.
2. **Recovery supervision used the blended executed action.** In the 75%
   assisted collection, `action` is the actor/teacher blend while
   `guide_action` is the recorded teacher target. Their fit-split translation
   difference reached 0.647 mm per 50 ms step. The builder now uses
   `guide_action`; unexecuted terminal padding is zero motion.
3. **The 200 ms endpoint discarded the recorded path.** Four different 50 ms
   teacher commands were integrated to one endpoint, after which the runtime
   reconstructed four equal interpolation steps. The corrected target contains
   the connector pose after each recorded command at 50/100/150/200 ms, all in
   one fixed port-opening frame. The adapter then recovers each TCP-body-frame
   target command from the four predicted waypoints. Reconstruction error is
   below 0.00003 mm.
4. **Checkpoint selection ignored real improvements.** Validation pose losses
   were around `3e-7`, while the required absolute improvement was `1e-7`.
   Consequently the old runs retained update 200 even as validation improved.
   Selection now uses mean physical translation error over the four-command
   online chunk, with a `1e-6 mm` tolerance. The saved compatibility field is
   still named `first_waypoint...`, but its implementation averages all four
   command errors.
5. **The live timeout disagreed with expert collection.** Development used six
   seconds while expert episodes used eight. The final comparison uses eight
   seconds. More time alone did not improve the diffusion arm beyond 2/6.

### What "small teacher-distribution error" means

Offline validation feeds observations recorded while the privileged teacher
kept the connector on successful trajectories, then compares the model command
with the teacher command. A small error proves imitation around those familiar
states. It does not prove that the policy can recover after one of its own
errors moves the system away from the teacher trajectory. The latter is the
closed-loop distribution shift seen in the failed live runs.

The original diagnostic dataset really did lack insertion: all 322 fit rows
were alignment. This was not true of all expert data. The replacement base
teacher run completed 32/32 fit starts and the later 823-row fit split contained
424 insertion decisions. The repaired DAgger split retains 980 low-force fit
decisions after rejecting stale reset images and force at or above 5 N.
Seventeen unsuccessful blended rollouts contribute only their recorded teacher
queries at safe states; their failed episode outcome is not represented as a
successful demonstration.

### Correct target and frame contract

For every 50 ms target command, the builder starts from the observation-only
connector estimate, maps it through the calibrated connector-to-TCP transform,
composes the **recorded teacher TCP-body-frame target**, and maps the resulting
connector pose into the fixed port-opening frame. The policy therefore predicts
four complete port-relative poses. It does not predict an additive correction,
an absolute base-frame coordinate, or simulator geometry.

```text
recorded teacher TCP-body command 1 --- compose ---> connector pose in port frame at  50 ms
recorded teacher TCP-body command 2 --- compose ---> connector pose in port frame at 100 ms
recorded teacher TCP-body command 3 --- compose ---> connector pose in port frame at 150 ms
recorded teacher TCP-body command 4 --- compose ---> connector pose in port frame at 200 ms
```

| Arm | Target / change | Strict insertion | Complete p95 latency |
| --- | --- | ---: | ---: |
| Old recovery-weighted diffusion | Blended action, 200 ms endpoints, 0.2 mm live clip | 0/6 | 60.22 ms |
| Frozen old arm, corrected 1.0 mm ceiling | Runtime-only check | 1/6 | 61.97 ms |
| Recorded target action, legacy 200 ms endpoint | Removes blended-label bug | 0/6 | 61.25 ms |
| Recorded 50 ms target waypoints, diffusion | Preserves all four target commands | 2/6 | 57.65 ms |

The selected direct arm has 2,004,329 trainable parameters and uses the same
536,631-parameter frozen perception stack, for 2,540,960 total parameters.
Across the 14 autonomous episodes it achieved 14/14 local 8 mm seats. Final
lateral error was 0.024--0.402 mm, orientation error was 0.002--0.066 degrees,
and post-reset maximum force was 1.69--3.69 N. There was no guide, guard,
exploration, simulator geometry, or RL at evaluation.

The deterministic result indicates that diffusion was harmful for this small,
nearly deterministic teacher dataset. It remains a valid research baseline,
but twenty denoising passes added latency and command-tail error without
providing a useful multimodal benefit.

## Final decision

The repaired deterministic AIC-RPDP BC arm passes the supervised development
gate and is the selected BC candidate. The earlier diffusion and DPPO branches
remain frozen failures; no additional RL was run in this continuation. The four
reserved final configurations remain sealed. Before any future DPPO round,
freeze this checkpoint and run the predeclared final evaluation or a larger
new-start development set, then base RL promotion on a matched comparison
against this 14/14 BC anchor.
