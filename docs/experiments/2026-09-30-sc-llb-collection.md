# SC Low Lateral Bypass collection

## Objective and gate

Collect approximately 200 **attempted** SC-to-SC teacher episodes with the Low Lateral Bypass (LLB) route. Count scored full insertions separately; do not label all attempts as expert successes. Run the first 30 distinct settings as a pilot. Continue toward 200 only if **at least 10 of those 30** have official full-insertion scores. Planning failures, simulator failures and aborted insertions remain in the 30-attempt denominator. If the gate fails, stop, inspect traces and videos, repair a specific cause, and rerun a fresh declared pilot. No BC training is part of this collection gate.

LLB sequence: back → left and descend below the card-top crossing corridor → forward beside the row → right → tilt at a clear pose → back to the selected port → guarded descent/insertion. The privileged teacher uses MoveIt rigid collision checking and Gazebo replay; planned waypoints and simulator geometry are never autonomous actor inputs.

## Pilot design

`scripts/prepare_sc_llb_collection.py` generates a deterministic 30-case manifest at `outputs/experiments/2026-09-30_sc_llb_collection/pilot30/`. It uses the frozen scored port-0/port-1 LLB references and transforms their routes to each new board pose and selected SC port, then requires MoveIt to solve against the new scene before Gazebo. The first 30 settings have **15 selected-port-0 and 15 selected-port-1 cases**, with **six each of one through five NIC cards**. They vary board X/Y/yaw, individual card positions/yaw, both SC rail translations and small cable grasp offsets; actual robot starts are fixed in this pilot, as audited below. The range is a conservative training pilot, not a final evaluation distribution claim. Every case stores the requested scene, start joints, route transform and exact config/route hashes. Four reserved final configurations are not opened.

The collection runner `scripts/run_sc_llb_collection.py` plans and replays cases sequentially on one project GPU via rootless Docker, writes `collection_progress.json` after each attempt, and stops after attempt 30 if fewer than ten score full insertion. It does not discard failed traces. Outputs include the exact MoveIt joint plan, scene, score, original three RGB cameras, two wide diagnostic views, raw bag, actor-independent teacher trace and launcher snapshots. The 20 fps video renderer can be run on selected successes/failures after scoring. At roughly 0.8 GB of raw output per episode, the pilot fits local free space; a 200-attempt continuation requires staged archive to the existing NAS before local capacity is exhausted. The NAS staging path is `/home/nas/chmin/aic_llb_collection_20260930/`.

Preparation: `.pixi/envs/default/bin/python scripts/prepare_sc_llb_collection.py --output outputs/experiments/2026-09-30_sc_llb_collection/pilot30 --count 30 --seed 20260930`. Collection: `.pixi/envs/default/bin/python scripts/run_sc_llb_collection.py outputs/experiments/2026-09-30_sc_llb_collection/pilot30 --pilot-only`. Per-case exact plan and replay commands, interfaces, scene hashes and status are retained in the case output directories. All teacher replays use `absolute_cartesian_pose_base_link`, the validated guarded SC insertion settings and the official frozen Gazebo scoring environment.

## Actual-start repair for the continuation

The first 30 manifest entries requested varied robot home joints, but the first scored trial of each scene actually starts from Gazebo's fixed xacro joints. The official engine reads the requested home joints but resets them only after that trial. The first 30 should therefore be described as varying the board, cards, selected port, SC rails and cable grasp, **not actual robot starts**.

For the 170 continuation cases, `scripts/prepare_sc_llb_start_variants.py` generated per-case `ur_llb_start.xacro` files and matching predicted MoveIt starts. `scripts/run_moveit_sc_route_pilot.sh` passes those descriptions to the frozen official Gazebo launch. The xacro was expanded successfully in the frozen container; actual variation must still be verified from a scored bag. `scripts/run_sc_llb_collection.py` checks the first observed six joints in every scored continuation bag, starting with `llb_0030`, and stops before the next case if the custom start fails to take effect or differs from the planner start by more than 0.015 rad. It also applies a second 10-of-30 insertion gate to the first 30 varied-start continuation cases before `llb_0060`. An audit of a pilot bag correctly returned false: the initial joints differed from the requested start by as much as 0.0369 rad and from the fixed reference by only 0.00026 rad.

The first 30 scored runs remain local. Each continuation run is copied to `/home/nas/chmin/aic_llb_collection_20260930/continuation170/` and checksummed before the local run is replaced with a symlink. Both collection phases run sequentially on GPU 7. The supervisor starts continuation only after the original 30-case gate passes and the pilot process exits. No BC training is running.
